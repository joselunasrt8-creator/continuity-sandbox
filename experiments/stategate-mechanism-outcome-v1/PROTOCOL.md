## Question and claim ceiling

Prospectively compare StateGate's exact-object validation/proof loop with (A) competent GitHub-native controls and (B) those controls plus a minimal evidence snapshot in one bounded, same-owner GitHub PR workflow. Outcomes may be improvement, null, harm, cost, blocked, or indeterminate. The benchmark cannot establish independent adoption/dependency, market demand, external economic validation, universal transferability, or that Continufy as a whole works.

This is not code correctness/security certification. Preserve:

```text
Instruction ≠ Authority
Evidence ≠ Decision
Decision ≠ Permission
Validation ≠ Execution
VALID ≠ Merge Authority
Proof ≠ Outcome
Outcome ≠ Automatic Governance Mutation
```

GitHub owner/operator permissions and repository rules remain authority and execution boundary. StateGate can only emit a required check and proof; it cannot grant merge authority, merge, manufacture evidence, or decide code correctness/security.

## Design and matching

Six semantic classes × four repetitions = 24 matched sets. Each set contains one isolated PR episode per arm, up to 72 episodes. Match the exact source-fixture tree, mutation bytes, canonical diff, actor/reviewer roles, native controls, CI, event schedule, and collection windows. `fixtures/BASE_TREE_MANIFEST.json` freezes every base file/path/mode and the exact root Git tree for each assigned arm; differences are limited to the assigned B snapshot or C StateGate workflow. `fixtures/FIXTURE_MANIFEST.json` freezes the matched source subtree and mutations. Use three disposable repositories (one per arm); never use production code/repositories. Before the cohort, create 24 protected target branches per repository at the recorded parentless arm base commit, exactly `bench/<scenario_id>/base`; each episode uses `bench/<scenario_id>/head` and targets only its unique base branch. Read back all target SHAs and effective controls before execution. No target branch is reset or reused, so an eligible merge cannot change another episode's base. The staged GitHub diff hash must be equal across A/B/C before a set can start. Randomize arm order within each set and scenario order from a recorded seed before the first episode. `SCENARIOS.json` freezes IDs, ground truth, event sequence, permitted deviations, fixture-state sequence, expected-diff preparation, branch isolation and deterministic scenario/arm order. A repetition is a separate disposable PR. All 72 episodes remain unrun under #43. If a mutation/event cannot be reproduced, stop the matched set as a deviation; do not replace it after observing results.

### Arm A — competent native baseline

All arms use the exact fixture CI in `fixture-ci.yml` and GitHub rulesets/branch protection on the protected default branch: PR required; one approving review; dismiss stale approval on new pushes; require approval of the most recent push; required `fixture-ci` check; strict up-to-date branch requirement; prohibit direct pushes; no administrator bypass during trial. Pin workflow/dependency references to full commit SHAs. Capture effective rule export/API response before cohort. PR author and approving reviewer must be distinct GitHub users; use only an already-authorized reviewer, with no external recruitment under #43. If no such account exists, or the GitHub account/plan cannot enforce PR, approval, stale/current-push review, and required-check behavior, future execution is `BLOCKED`; do not weaken the baseline. Enforce rules for administrators and configure no bypass actors. A human/operator separately authorizes any merge.

### Arm B — minimal snapshot comparator

Arm A plus included `snapshot-collector.mjs`, run by `snapshot-collector.yml` as a non-required diagnostic job on the same PR/review event. It uses Node built-in `fetch` and read-only `GITHUB_TOKEN` to write one JSON artifact containing separate trigger-payload and fetched PR identities, head/base, canonical diff SHA-256 using LF normalization plus one terminal LF (patch text/order preserved), reviews and review commit IDs/states/times, observation time, API provenance, workflow event/run/head, and source hashes. It brackets collection with two PR reads and two complete review reads; a head/base/`updated_at` or review-set change marks the artifact `INCONSISTENT_NOT_EVIDENCE` and exits nonzero, so mixed-object data cannot count. It does not issue an eligibility decision, fail a required check, or merge. It is intentionally dependency-free and smaller than the common collector; it does not implement StateGate policy, freshness rules, exact-object validation, or proof semantics. Same operator procedure applies across arms. Collector failure is missing evidence and does not change native gates.

### Arm C — StateGate required check

Arm A plus the workflow in `stategate-required-check.yml`, using `joselunasrt8-creator/stategate@dd6a607533b0c5c31eb99840e39d0a443998541a` (v1.1.1 full immutable commit; never floating `v1`). Enable `require-review-approval: 'true'`, `minimum-approvals: '1'`; provide repository, PR number, event head/base and actor; allow the pinned Action to acquire current PR/diff/reviews.

The expected diff is prepared **before** the event that evaluates it. Follow `fixtures/FIXTURE_MANIFEST.json`: create and push the intended H1/H2 commit to a non-PR staging ref, acquire the GitHub compare diff against the recorded base, canonicalize/hash it, set and read back repository variable `EXPECTED_DIFF_HASH`, and only then open or fast-forward the PR branch to that exact staged commit. For C2 and C3, configure H2 before advancing to H2; this makes stale review (C2) or current reapproval (C3), rather than a stale expected hash, the tested mechanism. C4 deliberately retains H1/O1 while advancing to H2/O2. C1/C5/C6 configure H1 before PR creation. Any unexpected first-run missing/mismatch is setup failure and blocks the episode; it is not rerun into compliance.

Require the exact `stategate` check in branch rules. Grant only `contents: read`, `pull-requests: read`, `actions: write` needed for documented proof upload. No contents/PR/checks write or merge capability. No StateGate code/schema/behavior/release changes.

The pinned release internally references `actions/upload-artifact@v4` from its composite Action. This transitive upload dependency is not modified; capture its resolved action identity from the future run record/log. If that identity or required artifact retention cannot be verified, stop before trials. The audited release interface normalizes reviews and binds current review head; compares acquired head/base against event inputs; binds canonical diff, review policy/evidence, decision and validator identity into proof; and fails closed when required evidence is missing, malformed, unavailable or inconsistent. `action.yml` uploads `MERGE_GUARD_PROOF.json`. Proof is validation evidence, not outcome/authority. Full commit `dd6a607533b0c5c31eb99840e39d0a443998541a` is the peeled v1.1.1 release tag target; the GitHub Release record itself is not marked immutable, so only the full commit SHA is used as the pin. ## Scenario semantics

`SCENARIOS.json` is authoritative for immutable scenario IDs, setup, event/mutation sequence, eligibility, evidence, observation, stop conditions and allowed deviations. Ground truth comes only from the frozen fixture and independently observed GitHub object/review state before viewing arm-specific results. Eligibility means the defined transition meets the frozen native review/identity/evidence preconditions at the decision point. Ineligible transitions are not merged; record gate result and stop. Eligible fixture PRs may be merged only by an authorized operator after evidence capture. Automated components never merge.

For event-sensitive scenarios preserve the raw event payload and its head/base/review identity separately from later API-observed PR state. `GITHUB_SHA` is workflow provenance, not the PR event head. A head changed after event creation makes the event object stale. Follow only each scenario’s explicit event sequence and captured payload; do not substitute `workflow_dispatch`; verify identity before scoring. No outcome relies on nondeterministic timing. If GitHub cannot reliably create the defined event sequence in a disposable repo, block rather than fabricate StateGate input.

## Common collector

Install `common-collector.yml` and byte-identical `common-collector.mjs` in all three repositories. This non-required, non-decision workflow runs on every specified PR/review event and on completion of the common Fixture CI only. Provision the same `BENCHMARK_ADMIN_READ_TOKEN` secret in every repository from a fine-grained PAT or GitHub App installation token limited to these disposable repositories and **Administration: read-only**, with no write permission. The built-in `GITHUB_TOKEN` remains read-only for ordinary PR/check/action acquisition; the separate credential is used only for branch-protection and ruleset GETs. Before the cohort, prove both configuration endpoints return HTTP 200 in all arms and record only credential class/installation identity, never token bytes. Missing or broader-than-required credential scope is `BLOCKED`. After the arm disposition is recorded, invoke exactly one `workflow_dispatch` with that PR number and `checkpoint=post-disposition` in every arm; this dispatch is collection only and never substitutes for a scenario decision event. Do not trigger on B snapshot or C StateGate completion, because that would give intervention arms extra measurement opportunities. The fixed collector runs and cost are retained as common instrumentation and excluded from arm-added overhead.

The executable collector freezes GitHub REST API version `2022-11-28`, endpoints, Accept headers, same-origin Link pagination (100/page; maximum 100 pages), serialization, raw response bodies/hashes, ETags, raw trigger payload/hash, run identity, and UTC start/end. It retrieves repository and PR state, canonical diff, commits, two independently paginated review reads, PR timeline, **all** check runs for the fetched head using `filter=all`, workflow runs/artifacts, branch protection, and rulesets. It reads PR state before and after all calls. A changed head/base/`updated_at` or changed normalized review set yields `INCONSISTENT_RETRY_FORBIDDEN_AS_EVIDENCE`, exits nonzero, and cannot supply decision evidence. A later event may produce its own packet; it does not repair or overwrite the inconsistent packet. This prevents sequential calls from silently combining objects.

Before each episode set/read back `BENCHMARK_SCENARIO_ID` and `BENCHMARK_ARM`; do not overlap episodes in a repository. The collector records those values and derives repetition from the ID. The operator waits for the arm disposition, then performs the one frozen post-disposition dispatch in every arm; any missing or extra dispatch is a deviation. Capture operator actions/active intervals in the separate contemporaneous ledger and link it by scenario/arm/run IDs. Missing evidence is missing; never backfill from memory. Equal observation window: first PR event to eligible merge or terminal ineligible/blocked state, capped at 30 active operator minutes and 24 wall-clock hours. Passive wait is excluded from active time.

`evidence-fields.json` freezes the terminal evidence-completeness denominator as 32 atomic, universally applicable fields per episode and supplies field-specific validity rules. Build each standardized mechanism packet only from that arm's eligible durable sources: GitHub-native surfaces for A; those plus the snapshot for B; those plus StateGate check/proof for C. The common collector is the answer key and cannot supply packet content. Empty eligible-source-proven arrays count as present; null, absent, invalid, inconsistent, inferred, or unverifiable fields score zero. Arm artifacts may supply a common field but never add denominator fields.

Outcome schema: `OUTCOME_OBJECT.schema.json`. One record per PR episode. Use JSON `null` when unavailable/not applicable and add a `missingness` entry for that exact field path. Schema and validator enforce this rule for every nullable measurement. No unavailable measurement may be encoded as zero. Count zero only if full event history was observed and no event occurred.

## Stops and deviations

Stop before any episode if the 24 isolated target branches per arm are not at their frozen bases with identical effective controls, native rules are not competent, immutable StateGate SHA cannot be resolved, the read-only configuration credential is missing/overbroad/insufficient, ground truth is ambiguous, or an arm workflow differs beyond its assigned intervention. Stop in flight on unexpected merge, unauthorized bypass, unrelated repository mutation, secret leak, identity loss, target-branch reuse, or sequence mismatch. Preserve evidence, mark set deviation/blocked, do not silently repair/retry. Technical interruption before scenario mutation may be retried once identically; retain both attempts and time. Any protocol/collector/scenario/rule/pin/metric/threshold edit requires a new version and prospective registration before new outcomes.
